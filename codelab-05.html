Inicio · pasar de una idea a una necesidad

Problema: una persona tiene actividades dispersas y necesita saber cuáles siguen pendientes. Usuario objetivo: estudiante que organiza tareas académicas. Alcance: funciones que sí se podrán demostrar al finalizar el curso. “Una app para organizar toda mi vida” es una idea amplia; “listar, consultar, crear, editar y eliminar tareas” delimita un producto verificable.

AlcanceConjunto de funciones incluidas en el proyecto. Ayuda a decidir qué se implementa primero y qué queda fuera.
Historia de usuarioFrase que explica quién necesita una función, qué quiere hacer y para qué: “Como estudiante, quiero ver mis tareas pendientes para planificar la semana”.
Criterio de aceptaciónCondición observable que permite comprobar una historia. Ejemplo: “La lista muestra el título y el estado de cada tarea”.

Requisito no funcionalCalidad esperada de esa acción, por ejemplo que un error se explique con un mensaje entendible.

2

Desarrollo A · decidir qué representa Task

Una entidad es un concepto del problema que tiene datos propios. Aquí la entidad es una tarea. Un modelo de datos es la clase Dart que representa esa entidad; no dibuja botones ni pantallas. Cada propiedad es un dato de la tarea y su tipo limita los valores que admite.

id: intNúmero único de la tarea. Permite abrir el detalle correcto desde la ruta /task/:id.
title: StringTexto corto que identifica la tarea en la lista.
description: StringTexto más extenso con información para el detalle.
priority: StringValor como Alta, Media o Baja; sirve para comunicar importancia.
isCompleted: booltrue indica completada y false indica pendiente.
userId: intIdentificador de la persona propietaria. En esta práctica se usa un usuario de prueba; no hay inicio de sesión todavía.

El modelo también define un constructor, que indica qué datos se entregan al crear una tarea. required obliga a proporcionar cada propiedad; final impide reasignarla después. const permite crear objetos inmutables cuando sus valores ya se conocen.

Ejemplo guiado · ejecutar el modelo sin interfaz

Crea la carpeta bin en la raíz de taskflow y, dentro, el archivo model_demo.dart. Pega el bloque completo. Es un programa Dart independiente para observar la conversión de JSON sin mezclarla con widgets.

import 'dart:convert';

class Task {
  const Task({
    required this.id,
    required this.title,
    required this.description,
    required this.priority,
    required this.isCompleted,
    required this.userId,
  });

  final int id;
  final String title;
  final String description;
  final String priority;
  final bool isCompleted;
  final int userId;

  factory Task.fromJson(Map<String, dynamic> json) {
    return Task(
      id: json['id'] as int,
      title: json['title'] as String,
      description: json['description'] as String,
      priority: json['priority'] as String,
      isCompleted: json['isCompleted'] as bool,
      userId: json['userId'] as int,
    );
  }
}

void main() {
  const response = '''
  {
    "id": 7,
    "title": "Preparar exposición",
    "description": "Organizar diapositivas y practicar",
    "priority": "Alta",
    "isCompleted": false,
    "userId": 1
  }
  ''';

  final json = jsonDecode(response) as Map<String, dynamic>;
  final task = Task.fromJson(json);
  print('Tarea ${task.id}: ${task.title}');
  print('Prioridad: ${task.priority}');
  print('Pendiente: ${!task.isCompleted}');
}
dart run bin/model_demo.dart

Resultado esperado: tres líneas: Tarea 7: Preparar exposición, Prioridad: Alta y Pendiente: true.

Cómo leerlo: JSON es texto con claves y valores. jsonDecode lo convierte en un mapa Dart; Map<String, dynamic> significa claves de texto y valores de distintos tipos. factory Task.fromJson es un constructor alternativo que procesa el mapa antes de crear un Task. as int y as String comprueban el tipo esperado y fallan si no coincide; si la API real usa otros nombres o tipos, este contrato tendrá que adaptarse. Consulta las guías oficiales de JSON en Dart y constructores.

El archivo bin/model_demo.dart es solo el ejercicio guiado. No lo incluyas en el commit del avance autónomo.

Desarrollo C · usar el modelo en lista y detalle

Para evitar piezas sueltas difíciles de ubicar, reemplaza todo el contenido de lib/main.dart por este archivo. Conserva el listado y la navegación de la sesión 4, y agrega userId en los datos. Si ya personalizaste tu aplicación, guarda antes una copia y reincorpora luego tus textos.

import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

import 'task.dart';

void main() {
  runApp(const TaskFlowApp());
}

const demoTasks = <Task>[
  Task(
    id: 1,
    title: 'Leer documentación',
    description: 'Revisar el material de Flutter',
    priority: 'Alta',
    isCompleted: false,
    userId: 1,
  ),
  Task(
    id: 2,
    title: 'Diseñar pantalla',
    description: 'Dibujar la lista de tareas',
    priority: 'Media',
    isCompleted: false,
    userId: 1,
  ),
  Task(
    id: 3,
    title: 'Preparar evidencia',
    description: 'Tomar capturas del avance',
    priority: 'Baja',
    isCompleted: true,
    userId: 1,
  ),
  Task(
    id: 4,
    title: 'Organizar pendientes',
    description: 'Ordenar actividades de la semana',
    priority: 'Alta',
    isCompleted: false,
    userId: 1,
  ),
  Task(
    id: 5,
    title: 'Revisar el proyecto',
    description: 'Ejecutar el análisis de Flutter',
    priority: 'Media',
    isCompleted: false,
    userId: 1,
  ),
];

Task? findTask(int? id) {
  for (final task in demoTasks) {
    if (task.id == id) return task;
  }
  return null;
}

final appRouter = GoRouter(
  routes: [
    GoRoute(
      path: '/',
      builder: (context, state) => const TaskListScreen(),
    ),
    GoRoute(
      path: '/task/:id',
      builder: (context, state) {
        final id = int.tryParse(state.pathParameters['id'] ?? '');
        return TaskDetailScreen(task: findTask(id));
      },
    ),
  ],
);

class TaskFlowApp extends StatelessWidget {
  const TaskFlowApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp.router(
      debugShowCheckedModeBanner: false,
      title: 'TaskFlow',
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.indigo),
      ),
      routerConfig: appRouter,
    );
  }
}

class TaskListScreen extends StatelessWidget {
  const TaskListScreen({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Mis tareas')),
      body: ListView.builder(
        padding: const EdgeInsets.all(16),
        itemCount: demoTasks.length,
        itemBuilder: (context, index) {
          final task = demoTasks[index];
          return Card(
            child: ListTile(
              leading: Icon(
                task.isCompleted
                    ? Icons.check_circle
                    : Icons.radio_button_unchecked,
              ),
              title: Text(task.title),
              subtitle: Text('Prioridad: ${task.priority}'),
              trailing: const Icon(Icons.chevron_right),
              onTap: () => context.push('/task/${task.id}'),
            ),
          );
        },
      ),
    );
  }
}

class TaskDetailScreen extends StatelessWidget {
  const TaskDetailScreen({super.key, required this.task});

  final Task? task;

  @override
  Widget build(BuildContext context) {
    final selected = task;
    return Scaffold(
      appBar: AppBar(title: const Text('Detalle de tarea')),
      body: Padding(
        padding: const EdgeInsets.all(24),
        child: selected == null
            ? const Text('No se encontró esta tarea.')
            : Column(
                crossAxisAlignment: CrossAxisAlignment.start,
                children: [
                  Text(
                    selected.title,
                    style: Theme.of(context).textTheme.headlineSmall,
                  ),
                  const SizedBox(height: 16),
                  Text(selected.description),
                  const SizedBox(height: 16),
                  Text('Prioridad: ${selected.priority}'),
                  Text(
                    selected.isCompleted
                        ? 'Estado: completada'
                        : 'Estado: pendiente',
                  ),
                  Text('Usuario: ${selected.userId}'),
                ],
              ),
      ),
    );
  }
}

Cómo funciona: import 'task.dart' conecta ambos archivos. demoTasks es una lista local de cinco objetos Task. ListView.builder construye una tarjeta por elemento. Al tocar una tarjeta, context.push abre la ruta que contiene su id; findTask busca el objeto correspondiente. El signo ? indica que una búsqueda puede no encontrar nada; por eso el detalle muestra un mensaje en lugar de fallar. StatelessWidget describe una pantalla cuyos datos locales no cambian durante esta práctica. Revisa la guía de rutas de go_router para reconocer el parámetro :id.

Abre el README.md de tu proyecto TaskFlow y agrega una sección como esta al final. No reemplaces las instrucciones de instalación que ya tengas. Cambia los textos para que describan tus cinco tareas reales.

## Alcance de TaskFlow

Problema: necesito organizar actividades académicas y saber cuáles faltan.
Usuario objetivo: estudiante que planifica entregas semanales.

### Historias de usuario y criterios de aceptación
1. Como estudiante, quiero listar mis tareas para ver qué debo hacer.
   Criterio: la lista muestra título, prioridad y estado de cada tarea.
2. Como estudiante, quiero abrir una tarea para leer su descripción.
   Criterio: al tocar una tarjeta aparece el detalle de la tarea elegida.
3. Como estudiante, quiero crear una tarea para registrar un pendiente.
   Criterio: el formulario guarda una tarea válida y la lista la muestra.
4. Como estudiante, quiero editar una tarea para corregir sus datos.
   Criterio: los cambios guardados aparecen en lista y detalle.
5. Como estudiante, quiero eliminar una tarea terminada para limpiar la lista.
   Criterio: después de confirmar, la tarea desaparece de la lista.

### Modelo de datos
Task: id (entero único), title (texto), description (texto),
priority (Alta, Media o Baja), isCompleted (verdadero/falso),
userId (entero que identifica al usuario de prueba).

### Pantallas previstas
Lista: tarjetas de tareas y acción para crear.
Detalle: información completa y futuras acciones de editar o eliminar.
Formulario: campos de título, descripción y prioridad.

### Requisitos no funcionales
La navegación debe tener textos comprensibles.
Un id inexistente debe mostrar un mensaje en vez de cerrar la app.

### Contrato de API que necesitaremos
GET /tasks        listar tareas
GET /tasks/:id    consultar detalle
POST /tasks       crear tarea
PATCH /tasks/:id  actualizar tarea
DELETE /tasks/:id eliminar tarea

La API concreta se elegirá después. Estas rutas son requisitos, no
direcciones de un servidor ya conectado.

Importante: un endpoint es una ruta de la API que ofrece una operación. GET consulta, POST crea, PATCH modifica parcialmente y DELETE elimina. Documentarlos ahora permite verificar después si una API real cubre el alcance. Las historias 3–5 se implementarán en sesiones posteriores; aquí se especifican.

Errores frecuentes y primera comprobación

“Task is defined twice”
Deja la clase Task solo en lib/task.dart; elimina la definición antigua de main.dart y conserva import 'task.dart'.
Falta userId
El constructor lo exige. Comprueba que cada Task(...) de demoTasks incluya userId: 1 u otro entero.
“Target of URI doesn't exist: go_router”
Desde taskflow, ejecuta flutter pub get. Si el paquete no figura en pubspec.yaml, usa flutter pub add go_router.
Error de tipo en fromJson
Revisa las claves y tipos del JSON. Este ejemplo espera exactamente isCompleted como booleano y userId como entero.
El detalle muestra otra tarea
Verifica que cada id sea único y que context.push('/task/${task.id}') use el id de la tarjeta tocada.
git push falla
Comprueba la rama con git branch --show-current y que el repositorio remoto esté configurado con git remote -v.
