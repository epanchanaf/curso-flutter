Separar TaskFlow en capas con MVVM

Vas a reorganizar la app de la sesión 5 sin perder su lista ni su pantalla de detalle. Al final, un botón cambiará el estado de una tarea y ambas pantallas se actualizarán.

1

Inicio · entender por qué separamos el código

Hasta ahora, main.dart contiene rutas, datos y pantallas. Si más adelante una API entrega las tareas, una pantalla que busque y modifique datos por su cuenta será difícil de cambiar. Una arquitectura es una forma de repartir responsabilidades entre partes del programa. MVVM significa Model, View y ViewModel:

Model · modeloRepresenta una tarea y sus propiedades. Aquí es la clase Task; no conoce botones ni pantallas.
View · vistaSon widgets que muestran datos y reciben toques. Aquí serán TaskListScreen y TaskDetailScreen.
ViewModelGuarda el estado que necesita la vista y ofrece acciones como toggleCompleted. No construye widgets.
Repository · repositorioOfrece operaciones sobre tareas y esconde de dónde vienen. Hoy usa una lista local; después podrá usar una API.
Service · servicioEn las siguientes sesiones, ApiService conocerá HTTP, URL y respuestas de la API. Esta sesión todavía no hace solicitudes de red.
ProviderPaquete que entrega una instancia del ViewModel a los widgets que la necesitan y permite escuchar sus cambios.

Recorrido actual: el usuario toca un botón en la View → la View llama al ViewModel → el ViewModel pide al Repository que guarde el cambio → el ViewModel avisa a la View → Flutter vuelve a dibujar los widgets que escuchan. Cuando se conecte la API, el Repository llamará también al Service.

Una dependencia es un objeto que otra clase necesita para trabajar. El ViewModel recibe un TaskRepository en su constructor; así no queda atado a una lista concreta. Inyectar una dependencia significa crearla fuera de la clase y entregársela, como haremos en main.dart.

Desarrollo B · completar el modelo Task

Abre lib/features/tasks/domain/task.dart y reemplaza su contenido completo por este bloque. Mantiene las seis propiedades de la sesión 5 y fromJson. El nuevo método copyWith crea otra tarea con el estado cambiado, sin modificar el objeto original.

class Task {
  const Task({
    required this.id,
    required this.title,
    required this.description,
    required this.priority,
    required this.isCompleted,
    required this.userId,
  });

  final int id;
  final String title;
  final String description;
  final String priority;
  final bool isCompleted;
  final int userId;

  Task copyWith({bool? isCompleted}) {
    return Task(
      id: id,
      title: title,
      description: description,
      priority: priority,
      isCompleted: isCompleted ?? this.isCompleted,
      userId: userId,
    );
  }

  factory Task.fromJson(Map<String, dynamic> json) {
    return Task(
      id: json['id'] as int,
      title: json['title'] as String,
      description: json['description'] as String,
      priority: json['priority'] as String,
      isCompleted: json['isCompleted'] as bool,
      userId: json['userId'] as int,
    );
  }
}
Cómo leerlo: final impide cambiar una propiedad después de construir el objeto. bool? significa que el parámetro admite true, false o null. ?? conserva el valor anterior si no se entregó otro. fromJson se mantiene para cuando llegue información de la API; todavía no se usa en esta práctica.

Desarrollo C · definir el contrato del repositorio

Crea lib/features/tasks/data/task_repository.dart y pega el archivo completo. Una clase abstracta define qué operaciones deben existir, pero no decide cómo se realizan. List<Task> es una lista cuyos elementos son tareas.

import '../domain/task.dart';

abstract class TaskRepository {
  List<Task> getTasks();
  void save(Task task);
}

getTasks entrega las tareas. save reemplaza una tarea por otra que tenga el mismo id. Este es un contrato inicial para datos locales; al conectar la API, las operaciones se adaptarán para esperar respuestas asíncronas.

Ahora crea lib/features/tasks/data/local_task_repository.dart y pega este archivo completo. Aquí viven los datos de ejemplo que antes estaban en main.dart.

import '../domain/task.dart';
import 'task_repository.dart';

class LocalTaskRepository implements TaskRepository {
  final List<Task> _tasks = [
    const Task(
      id: 1,
      title: 'Leer documentación',
      description: 'Revisar el material de Flutter',
      priority: 'Alta',
      isCompleted: false,
      userId: 1,
    ),
    const Task(
      id: 2,
      title: 'Diseñar pantalla',
      description: 'Dibujar la lista de tareas',
      priority: 'Media',
      isCompleted: false,
      userId: 1,
    ),
    const Task(
      id: 3,
      title: 'Preparar evidencia',
      description: 'Tomar capturas del avance',
      priority: 'Baja',
      isCompleted: true,
      userId: 1,
    ),
  ];

  @override
  List<Task> getTasks() => List.unmodifiable(_tasks);

  @override
  void save(Task task) {
    final index = _tasks.indexWhere((item) => item.id == task.id);
    if (index == -1) return;
    _tasks[index] = task;
  }
}
Cómo leerlo: implements obliga a escribir las operaciones del contrato. _tasks es privado dentro de este archivo. List.unmodifiable entrega una lista que la pantalla no puede alterar directamente. indexWhere busca la posición del id; devuelve -1 si no existe. Estos datos están en memoria: al reiniciar la app vuelven a su valor inicial. La persistencia se verá después.

Desarrollo D · crear el ViewModel y avisar de los cambios

Crea lib/features/tasks/presentation/tasks_view_model.dart y pega el archivo completo. ChangeNotifier es una clase de Flutter que permite avisar a los widgets cuando cambia el estado. El ViewModel recibe el repositorio, carga la lista y ofrece una acción para alternar entre pendiente y completada.

import 'package:flutter/foundation.dart';

import '../data/task_repository.dart';
import '../domain/task.dart';

class TasksViewModel extends ChangeNotifier {
  TasksViewModel(TaskRepository repository)
      : _repository = repository,
        _tasks = repository.getTasks();

  final TaskRepository _repository;
  List<Task> _tasks;

  List<Task> get tasks => List.unmodifiable(_tasks);

  Task? findTask(int? id) {
    if (id == null) return null;
    for (final task in _tasks) {
      if (task.id == id) return task;
    }
    return null;
  }

  void toggleCompleted(int id) {
    final current = findTask(id);
    if (current == null) return;

    _repository.save(
      current.copyWith(isCompleted: !current.isCompleted),
    );
    _tasks = _repository.getTasks();
    notifyListeners();
  }
}
Cómo leerlo: el constructor recibe TaskRepository y toma una primera copia de las tareas. El signo ? de Task? indica que una búsqueda puede no encontrar nada. ! delante de current.isCompleted invierte true y false. Después de guardar, el ViewModel vuelve a leer el repositorio y llama a notifyListeners(); eso solicita actualizar las vistas que lo escuchan.

Desarrollo E · separar la lista y el detalle

Crea lib/features/tasks/presentation/task_list_screen.dart con este archivo completo. context.watch<TasksViewModel>() obtiene el ViewModel y vuelve a construir esta pantalla cuando el ViewModel avisa un cambio. La vista solo presenta datos y comunica la navegación.

import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';
import 'package:provider/provider.dart';

import 'tasks_view_model.dart';

class TaskListScreen extends StatelessWidget {
  const TaskListScreen({super.key});

  @override
  Widget build(BuildContext context) {
    final tasks = context.watch<TasksViewModel>().tasks;

    return Scaffold(
      appBar: AppBar(title: const Text('Mis tareas')),
      body: ListView.builder(
        padding: const EdgeInsets.all(16),
        itemCount: tasks.length,
        itemBuilder: (context, index) {
          final task = tasks[index];
          return Card(
            child: ListTile(
              leading: Icon(
                task.isCompleted
                    ? Icons.check_circle
                    : Icons.radio_button_unchecked,
              ),
              title: Text(task.title),
              subtitle: Text('Prioridad: ${task.priority}'),
              trailing: const Icon(Icons.chevron_right),
              onTap: () => context.push('/task/${task.id}'),
            ),
          );
        },
      ),
    );
  }
}

Crea lib/features/tasks/presentation/task_detail_screen.dart con este archivo completo. La ruta entrega el id; el ViewModel busca la tarea. context.read llama a la acción al tocar el botón, sin suscribir ese callback a cambios.

import 'package:flutter/material.dart';
import 'package:provider/provider.dart';

import 'tasks_view_model.dart';

class TaskDetailScreen extends StatelessWidget {
  const TaskDetailScreen({super.key, required this.taskId});

  final int? taskId;

  @override
  Widget build(BuildContext context) {
    final task = context.watch<TasksViewModel>().findTask(taskId);

    return Scaffold(
      appBar: AppBar(title: const Text('Detalle de tarea')),
      body: task == null
          ? const Center(child: Text('No se encontró esta tarea.'))
          : ListView(
              padding: const EdgeInsets.all(24),
              children: [
                Text(
                  task.title,
                  style: Theme.of(context).textTheme.headlineSmall,
                ),
                const SizedBox(height: 16),
                Text(task.description),
                const SizedBox(height: 16),
                Text('Prioridad: ${task.priority}'),
                Text(
                  task.isCompleted
                      ? 'Estado: completada'
                      : 'Estado: pendiente',
                ),
                Text('Usuario: ${task.userId}'),
                const SizedBox(height: 24),
                ElevatedButton(
                  onPressed: () {
                    context.read<TasksViewModel>().toggleCompleted(task.id);
                  },
                  child: Text(
                    task.isCompleted
                        ? 'Marcar como pendiente'
                        : 'Marcar como completada',
                  ),
                ),
              ],
            ),
    );
  }
}
Diferencia entre watch y read: watch escucha los cambios porque el método build necesita volver a dibujar datos. read solo obtiene el objeto para ejecutar una acción en onPressed. StatelessWidget puede actualizarse aquí porque Provider provoca un nuevo build al recibir notifyListeners().

Desarrollo F · conectar tema, rutas y Provider

Crea lib/core/app_theme.dart. El tema centraliza los colores y estilos comunes; por eso va en core.

import 'package:flutter/material.dart';

final ThemeData appTheme = ThemeData(
  colorScheme: ColorScheme.fromSeed(seedColor: Colors.indigo),
);

Crea lib/app/taskflow_app.dart. Una ruta relaciona una dirección, como /task/2, con una pantalla. int.tryParse convierte el id de texto a número; si no es válido, entrega null y el detalle muestra un mensaje.

import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

import '../core/app_theme.dart';
import '../features/tasks/presentation/task_detail_screen.dart';
import '../features/tasks/presentation/task_list_screen.dart';

final GoRouter appRouter = GoRouter(
  routes: [
    GoRoute(
      path: '/',
      builder: (context, state) => const TaskListScreen(),
    ),
    GoRoute(
      path: '/task/:id',
      builder: (context, state) {
        final id = int.tryParse(state.pathParameters['id'] ?? '');
        return TaskDetailScreen(taskId: id);
      },
    ),
  ],
);

class TaskFlowApp extends StatelessWidget {
  const TaskFlowApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp.router(
      debugShowCheckedModeBanner: false,
      title: 'TaskFlow',
      theme: appTheme,
      routerConfig: appRouter,
    );
  }
}

Por último, reemplaza todo lib/main.dart por este archivo. ChangeNotifierProvider crea y entrega un ViewModel a las pantallas. Como se ubica por encima de TaskFlowApp, la lista y el detalle pueden usar la misma instancia.

import 'package:flutter/material.dart';
import 'package:provider/provider.dart';

import 'app/taskflow_app.dart';
import 'features/tasks/data/local_task_repository.dart';
import 'features/tasks/data/task_repository.dart';
import 'features/tasks/presentation/tasks_view_model.dart';

void main() {
  final TaskRepository repository = LocalTaskRepository();

  runApp(
    ChangeNotifierProvider<TasksViewModel>(
      create: (_) => TasksViewModel(repository),
      child: const TaskFlowApp(),
    ),
  );
}

Punto de control: main.dart ya no declara Task, demoTasks, pantallas ni rutas. Si el analizador indica una importación inexistente, compara el nombre y la carpeta de cada archivo con el árbol del paso 2.

Errores frecuentes y primera comprobación

No encuentra provider
Comprueba que estás en taskflow, ejecuta flutter pub add provider y después flutter pub get.
No encuentra task.dart
Confirma que está en lib/features/tasks/domain/ y que los import usan las rutas relativas mostradas.
“Task is defined twice”
Deja una sola declaración de class Task, en domain/task.dart. Reemplaza el contenido antiguo de main.dart.
“ProviderNotFoundException”
Confirma que ChangeNotifierProvider envuelve a TaskFlowApp en main.dart; detén y vuelve a iniciar la app.
La lista no se actualiza
Verifica que toggleCompleted llame a notifyListeners() y que la lista use context.watch dentro de build.
El cambio desaparece al reiniciar
Es el comportamiento esperado de LocalTaskRepository: la lista está en memoria. Más adelante se conectará una fuente persistente.
git push falla
Consulta la rama con git branch --show-current y el remoto con git remote -v antes de repetir el comando.
