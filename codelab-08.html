Inicio · reconocer los cuatro estados

Una operación asíncrona tarda un tiempo desconocido. Durante ese tiempo, la interfaz necesita un estado: información que indica qué debe dibujarse. ChangeNotifier avisa cuando cambia el estado y context.watch reconstruye la pantalla. El Repository sigue ocultando el origen de los datos y el Service sigue siendo el único que conoce Dio.

CargaLa petición sigue pendiente. Se muestra un indicador y se evita repetirla varias veces.
ÉxitoLa respuesta contiene tareas. Se dibuja una tarjeta por cada Task.
VacíoLa petición terminó bien, pero la lista contiene cero tareas. Se muestra un mensaje y una acción para actualizar.
ErrorLa petición falló por red, servidor o formato. Se muestra un mensaje comprensible y Reintentar.

Regla: vacío y error son distintos. Una lista vacía es una respuesta válida; un error significa que no sabemos qué tareas hay. El detalle y la acción local de marcar completada seguirán funcionando como en la sesión 7.

Desarrollo A · completar el ViewModel

Reemplaza todo lib/features/tasks/presentation/tasks_view_model.dart por este archivo. loadTasks() servirá tanto para la primera carga como para Reintentar y Actualizar. errorMessage se limpia antes de cada intento. El catch guarda un mensaje para la vista y la excepción técnica se deja en la consola para diagnóstico.

import 'package:flutter/foundation.dart';

import '../data/task_repository.dart';
import '../domain/task.dart';

class TasksViewModel extends ChangeNotifier {
  TasksViewModel(this._repository);

  final TaskRepository _repository;
  List<Task> _tasks = [];
  bool isLoading = false;
  String? errorMessage;

  List<Task> get tasks => List.unmodifiable(_tasks);
  bool get isEmpty => !isLoading && errorMessage == null && _tasks.isEmpty;

  Future<void> loadTasks() async {
    if (isLoading) return;
    isLoading = true;
    errorMessage = null;
    notifyListeners();

    try {
      _tasks = await _repository.getTasks();
    } catch (error) {
      _tasks = [];
      errorMessage = 'No se pudieron cargar las tareas.';
      debugPrint('Error al cargar tareas: $error');
    } finally {
      isLoading = false;
      notifyListeners();
    }
  }

  Task? findTask(int? id) {
    if (id == null) return null;
    for (final task in _tasks) {
      if (task.id == id) return task;
    }
    return null;
  }

  void toggleCompleted(int id) {
    final current = findTask(id);
    if (current == null) return;
    final updated = current.copyWith(isCompleted: !current.isCompleted);
    _repository.save(updated);
    _tasks = [
      for (final task in _tasks) if (task.id == id) updated else task,
    ];
    notifyListeners();
  }
}
Cómo leerlo: Future<void> indica que la operación termina más tarde y no devuelve un dato. if (isLoading) return evita dos solicitudes simultáneas. try intenta cargar; catch maneja el fallo; finally termina la carga en ambos casos. notifyListeners() pide a las vistas suscritas que se reconstruyan.

Desarrollo B · construir la lista con acciones

Reemplaza todo lib/features/tasks/presentation/task_list_screen.dart. context.watch lee el estado para dibujar. context.read ejecuta una acción desde el botón sin crear una escucha adicional. RefreshIndicator permite actualizar deslizando hacia abajo.

import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';
import 'package:provider/provider.dart';

import 'tasks_view_model.dart';

class TaskListScreen extends StatelessWidget {
  const TaskListScreen({super.key});

  @override
  Widget build(BuildContext context) {
    final viewModel = context.watch<TasksViewModel>();

    return Scaffold(
      appBar: AppBar(
        title: const Text('Mis tareas'),
        actions: [
          IconButton(
            tooltip: 'Actualizar tareas',
            onPressed: viewModel.isLoading
                ? null
                : () => context.read<TasksViewModel>().loadTasks(),
            icon: const Icon(Icons.refresh),
          ),
        ],
      ),
      body: _buildBody(context, viewModel),
    );
  }

  Widget _buildBody(BuildContext context, TasksViewModel viewModel) {
    if (viewModel.isLoading) {
      return const Center(child: CircularProgressIndicator());
    }
    if (viewModel.errorMessage != null) {
      return Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            Text(viewModel.errorMessage!),
            const SizedBox(height: 12),
            ElevatedButton(
              onPressed: () => context.read<TasksViewModel>().loadTasks(),
              child: const Text('Reintentar'),
            ),
          ],
        ),
      );
    }
    if (viewModel.isEmpty) {
      return Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            const Text('Todavía no hay tareas para mostrar.'),
            const SizedBox(height: 12),
            ElevatedButton(
              onPressed: () => context.read<TasksViewModel>().loadTasks(),
              child: const Text('Actualizar'),
            ),
          ],
        ),
      );
    }

    return RefreshIndicator(
      onRefresh: () => context.read<TasksViewModel>().loadTasks(),
      child: ListView.builder(
        physics: const AlwaysScrollableScrollPhysics(),
        padding: const EdgeInsets.all(16),
        itemCount: viewModel.tasks.length,
        itemBuilder: (context, index) {
          final task = viewModel.tasks[index];
          return Card(
            child: ListTile(
              leading: Icon(task.isCompleted
                  ? Icons.check_circle
                  : Icons.radio_button_unchecked),
              title: Text(task.title),
              subtitle: Text('Prioridad: ${task.priority}'),
              trailing: const Icon(Icons.chevron_right),
              onTap: () => context.push('/task/${task.id}'),
            ),
          );
        },
      ),
    );
  }
}

Punto de control: con internet verás las tareas remotas. El botón de la barra y el gesto de deslizar vuelven a pedir datos. Una actualización vuelve a leer el servidor; por eso una marca local de completada puede desaparecer, como se explicó en la sesión 7.

  1. Éxito: con internet, abre una tarea y vuelve. El título y el id deben corresponder al elemento tocado.
  2. Error y reintento: desactiva internet del emulador, pulsa Actualizar y espera el mensaje. Reactiva internet y pulsa Reintentar; la lista debe volver sin reiniciar TaskFlow.
  3. Vacío: en TaskApiService, cambia temporalmente la constante userId por 9999, reinicia la app y comprueba el mensaje “Todavía no hay tareas”. Restaura tu valor válido al terminar.
  4. Carga: observa el indicador durante la petición. Si la red responde demasiado rápido, usa la limitación de red del emulador; no agregues una espera artificial al código final.

El botón Reintentar solo aparece después de un error; Actualizar aparece cuando la respuesta fue válida pero no contiene tareas. Esta diferencia es la evidencia central de la sesión.

Errores frecuentes

El indicador no desaparece
Comprueba que isLoading = false y notifyListeners() estén dentro de finally.
Reintentar no hace nada
Verifica que el botón llame a loadTasks() mediante context.read y que el emulador tenga internet.
El vacío aparece como error
Comprueba que la API respondió con una lista vacía. No lances una excepción solo porque no haya tareas.
El detalle deja de encontrar la tarea
No cambies las rutas ni task_detail_screen.dart; revisa que cada tarjeta navegue con task.id.
La marca local se pierde al actualizar
Es esperado: actualizar pide de nuevo la versión remota. La persistencia de cambios se estudiará en las sesiones de CRUD.
