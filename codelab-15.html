Preparar TaskFlow

Inicio · 15 min; desarrollo y ejemplo guiado · 75 min; cierre y trabajo autónomo · 30 min. Parte de todas las funcionalidades anteriores. Recupera el README real de tu proyecto y verifica los flujos antes de refactorizar. Ejecuta primero los comandos desde la raíz de taskflow. Si el proyecto no compila, recupera el último commit funcional antes de avanzar.

flutter pub get
flutter analyze
flutter run

Punto de control: abre la lista y el detalle de una tarea; ambos deben conservar el avance de la sesión anterior.

1

Conceptos antes de programar

RefactorizarOrdenar código sin cambiar su comportamiento observable.
Análisis estáticoflutter analyze detecta problemas sin ejecutar la app.
Prueba repetibleflutter test comprueba reglas de forma automática.
READMEDocumento de entrada que explica propósito, instalación, arquitectura, API y limitaciones.
2

Crear la lista de verificación

Revisa uno por uno: inicio, lista, detalle, formulario, CRUD, error, búsqueda y configuración. Marca como pendiente lo que no funciona y resuelve primero los flujos esenciales.

[ ] La app inicia y consulta la API
[ ] Lista y detalle muestran la tarea correcta
[ ] Crear, editar y eliminar muestran éxito o error
[ ] Reintentar recupera una carga fallida
[ ] Filtros y preferencias funcionan
[ ] flutter analyze y flutter test terminan bien

No afirmes en el README que JSONPlaceholder guarda cambios permanentes.

3

Ordenar el código

Ejecuta estas comprobaciones. Corrige cada error mostrado antes de compilar el APK.

dart format lib test
flutter analyze
flutter test

El formato modifica espacios y saltos de línea; el analizador detecta imports, tipos y usos incorrectos.

4

Completar el README

En el README de TaskFlow, conserva lo existente y agrega estas secciones con datos reales de tu proyecto.

## TaskFlow
Problema y usuario objetivo.

## Requisitos
Flutter SDK, Android SDK y un emulador o teléfono.

## Instalación
flutter pub get
flutter run

## Arquitectura
View → ViewModel → Repository → TaskApiService → API.

## API y limitaciones
URL, endpoints, campos JSON y qué cambios son simulados.

## Pruebas
flutter analyze
flutter test

## Capturas
Lista, detalle, formulario y manejo de errores.

Explica los nombres de archivos y rutas para que otra persona sepa dónde empezar.

5

Revisión por pares

Pide a otra persona que siga solo el README para ejecutar la app. Anota cada paso que requiera explicación oral y corrige el documento.

git diff --check
git status

No añadas claves, tokens, contraseñas ni archivos de configuración privados al repositorio.

6

Comprobar y subir el avance

Comprueba que todas las afirmaciones del README coinciden con la app real. Revisa el diff antes de crear el commit.

dart format lib
flutter analyze
flutter test
git status
git add README.md lib test pubspec.yaml pubspec.lock
git commit -m "docs: preparar documentación de entrega"
git push origin main

Si tu rama no se llama main, usa el nombre que muestra git branch --show-current. Comprueba el commit en GitHub; el ejemplo guiado no se versiona como evidencia aislada.
