Construir el APK y presentar TaskFlow por escrito

La entrega final reúne el APK, una presentación escrita breve y enlaces verificables al trabajo de las 16 sesiones.

Resultado observable: el repositorio contiene una presentación escrita con URL del proyecto, historial remoto de al menos 16 commits, cuatro capturas seleccionadas, explicación de la API y limitaciones, junto con un APK instalable.
0

Preparar TaskFlow

Inicio · 15 min; desarrollo y ejemplo guiado · 75 min; cierre y trabajo autónomo · 30 min. Parte del proyecto documentado y verificado en la sesión 15. Usa un dispositivo Android o emulador y conserva la configuración de firma del proyecto. Ejecuta primero los comandos desde la raíz de taskflow. Si el proyecto no compila, recupera el último commit funcional antes de avanzar.

flutter pub get
flutter analyze
flutter run

Punto de control: abre la lista y el detalle de una tarea; ambos deben conservar el avance de la sesión anterior.

1

Conceptos antes de programar

APKArchivo instalable de Android.
ReleaseCompilación optimizada para entrega, distinta de la ejecución de desarrollo.
Prueba de aceptaciónRecorrido manual que confirma las acciones que una persona necesita completar.
Presentación escritaDocumento breve con enlaces verificables, capturas legibles y explicación técnica; se entrega para lectura, sin exposición oral.
Commit remotoVersión guardada en Git que ya aparece en GitHub. La entrega enlaza un commit distinto por cada sesión.
2

Ejecutar controles finales

Desde la raíz de TaskFlow, corre los tres controles antes de generar el artefacto.

dart format lib test
flutter analyze
flutter test

Si falla un control, corrige el proyecto antes de continuar.

3

Generar el APK

Compila para Android. La primera compilación puede tardar varios minutos.

flutter build apk --release

Busca el resultado en build/app/outputs/flutter-apk/app-release.apk. El tamaño y tiempo dependen del proyecto.

4

Instalar y probar el artefacto

Con un teléfono conectado o emulador activo, instala el APK construido y abre TaskFlow desde el lanzador de Android.

flutter devices
flutter install --release

Comprueba lista, detalle, formulario, respuesta de error y recuperación. Si la app release no llega a la API, verifica el permiso INTERNET en el manifest principal.

5

Preparar la presentación escrita

Crea docs/entrega-final.md en tu proyecto TaskFlow y una carpeta docs/capturas/. La presentación es un documento para leer: no se pide exposición oral ni video. Usa cuatro capturas legibles que muestren el resultado, no una imagen por cada pantalla. Evita datos personales y recorta áreas del emulador que no aporten evidencia.

Copia esta plantilla y reemplaza cada texto entre corchetes por datos reales. Los enlaces de commit deben abrir un commit concreto en GitHub; no basta con pegar la URL general del repositorio en las 16 filas.

6

Comprobar y subir el avance

Instala y abre el APK; confirma el flujo esencial. Abre docs/entrega-final.md en GitHub para comprobar que sus enlaces y cuatro imágenes se muestran, y verifica al menos 16 commits remotos en el historial.

dart format lib
flutter analyze
flutter test
git status
git add README.md lib test pubspec.yaml pubspec.lock docs
git commit -m "build: preparar entrega final"
git push origin main

Si tu rama no se llama main, usa el nombre que muestra git branch --show-current. Comprueba el commit final en GitHub, copia su URL a la fila 16 de la presentación y sube esa actualización si hace falta. Comprueba también que las capturas se ven y que los 16 enlaces abren los commits correctos.

Errores frecuentes y primera acción

No se genera APK
Lee la primera causa de error de Gradle y revisa flutter doctor.
Release no tiene internet
Comprueba el permiso INTERNET en android/app/src/main/AndroidManifest.xml.
Una captura o enlace no aparece en GitHub
Revisa la ruta relativa desde docs/entrega-final.md hacia capturas/, agrega los archivos y haz push. Para los commits, copia la URL de cada commit desde el historial remoto.
flutter install no encuentra dispositivo
Inicia el emulador o conecta el teléfono y repite flutter devices.
