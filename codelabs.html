Crear la aplicación y su primera pantalla

Abre lib/main.dart, elimina el contenido generado y pega el siguiente código completo. main() es el inicio de Dart; runApp() entrega a Flutter el widget raíz que debe dibujar.

import 'package:flutter/material.dart';

void main() {
  runApp(const TaskFlowApp());
}

class TaskFlowApp extends StatelessWidget {
  const TaskFlowApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(

      title: 'TaskFlow',
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.indigo),
        useMaterial3: true,

}

class WelcomeScreen extends StatelessWidget {

  @override

    const pendingTasks = 3;
    const courseName = 'Desarrollo de aplicaciones móviles';

    return Scaffold(
      appBar: AppBar(
        title: const Text('TaskFlow'),
        centerTitle: true,
      ),
      body: Padding(
        padding: const EdgeInsets.all(24),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            const Icon(Icons.check_circle_outline, size: 56),
            const SizedBox(height: 24),
            Text(
              '¡Hola, $studentName!',
              style: Theme.of(context).textTheme.headlineMedium,
            ),
            const SizedBox(height: 12),
            Text('Bienvenido/a a $courseName.'),
            const SizedBox(height: 32),

0

  2. 10–25 min: transformar la pantalla en StatefulWidget.
  3. 25–45 min: crear acciones que agregan y completan tareas.
  4. 45–70 min: componer el panel reactivo y analizar los widgets.
  5. 70–95 min: probar todos los estados, formatear y analizar.
  6. 95–120 min: completar el trabajo autónomo incremental y registrar el commit.
cd taskflow
flutter run

Punto de control: antes de editar debes ver la bienvenida de la sesión 1 con el contador fijo. Si no inicia, resuelve primero ese problema para no confundirlo con un error de esta sesión.

1

Concepto central: estado local

Un widget describe la interfaz a partir de su configuración y estado. Según la documentación oficial de Flutter, al cambiar el estado el framework vuelve a construir la descripción de la UI y determina los cambios mínimos que debe aplicar. En TaskFlow, pendingTasks es la única fuente de verdad: no se modifica un texto en pantalla; se modifica ese número y se deja que build() produzca la nueva pantalla.

EstadoInformación que puede cambiar durante la vida de la pantalla: el número de tareas pendientes.
build(context)Función que devuelve el árbol de widgets para el estado actual. No guarda el contador.
setState()Notifica que el estado interno cambió y programa una nueva ejecución de build().
Lectura obligatoria: la API oficial define StatefulWidget como un widget con estado mutable y explica que setState ejecuta su callback de forma síncrona; no se usa con async dentro del callback.
2

Conserva main() y TaskFlowApp de la sesión 1. Reemplaza la clase WelcomeScreen por este esqueleto. La clase pública del widget permanece inmutable; la clase privada _WelcomeScreenState contiene los datos mutables.

Guarda y usa Hot Reload. Debes ver el texto temporal. Si aparece un error de sintaxis, compara cada llave, paréntesis y punto y coma con el bloque.

¿Por qué hay dos clases?

Las instancias de StatefulWidget son inmutables. Flutter crea un objeto State separado para conservar la información mutable mientras esa ubicación del árbol siga existiendo. Por eso pendingTasks va en _WelcomeScreenState.

3

Paso B — modelar las dos acciones (25–45 min)

Dentro de _WelcomeScreenState, arriba de build(), agrega el nombre y los métodos. El guion bajo indica que son detalles privados del archivo. La guarda de _completeTask protege la regla del dominio: no existen tareas pendientes negativas.

final String studentName = 'Escribe tu nombre';

void _addTask() {
  setState(() {
    pendingTasks++;
  });
}

void _completeTask() {
  if (pendingTasks == 0) {
    return;
  }

  setState(() {
    pendingTasks--;
  });
}
Evita este error: pendingTasks--; fuera de setState cambia el valor en memoria, pero Flutter podría no programar un nuevo build(). El callback de setState contiene solo la mutación del estado, no esperas de red ni cálculos costosos.
4

Paso C — reemplazar el build temporal (45–70 min)

Ahora sustituye solo el método build() del paso A por el siguiente. statusMessage es un valor derivado: se calcula cada vez desde pendingTasks, por lo que nunca queda desincronizado.

@override
Widget build(BuildContext context) {
  final statusMessage = pendingTasks == 0
      ? '¡Excelente! No tienes tareas pendientes.'
      : 'Aún tienes tareas por organizar.';

  return Scaffold(
    appBar: AppBar(title: const Text('TaskFlow'), centerTitle: true),
    body: Padding(
      padding: const EdgeInsets.all(24),
      child: Column(
        crossAxisAlignment: CrossAxisAlignment.start,
        children: [
          Text('¡Hola, $studentName!',
            style: Theme.of(context).textTheme.headlineMedium),
          const SizedBox(height: 12),
          Text(statusMessage),
          const SizedBox(height: 28),
          Card(child: Padding(
            padding: const EdgeInsets.all(20),
            child: Row(children: [
              const Icon(Icons.pending_actions),
              const SizedBox(width: 12),
              Text('Tareas pendientes: $pendingTasks'),
            ]),
          )),
          const SizedBox(height: 24),
          Wrap(spacing: 12, runSpacing: 12, children: [
            ElevatedButton.icon(
              onPressed: _addTask,
              icon: const Icon(Icons.add),
              label: const Text('Agregar tarea'),
            ),
            OutlinedButton.icon(
              onPressed: pendingTasks == 0 ? null : _completeTask,
              icon: const Icon(Icons.done),
              label: const Text('Completar una tarea'),
            ),
          ]),
        ],
      ),
    ),
  );
}

Resultado esperado: “Agregar tarea” aumenta el contador; “Completar una tarea” lo disminuye; al llegar a cero cambia el mensaje y se deshabilita completar.

1

Identificar qué dato debe cambiar

En la sesión anterior, pendingTasks era una constante. Pero una tarea pendiente puede agregarse o completarse. Esa información que cambia y obliga a redibujar la interfaz se llama estado.

Idea clave: no se cambia el texto directamente. Se cambia el estado y Flutter ejecuta otra vez build() para describir la nueva pantalla.
2

Convertir la pantalla en StatefulWidget

Conserva main() y TaskFlowApp. Reemplaza solamente la clase WelcomeScreen por este bloque. Ahora hay dos clases: el widget inmutable y la clase privada que contiene su estado modificable.

class WelcomeScreen extends StatefulWidget {
  const WelcomeScreen({super.key});

  @override
  State<WelcomeScreen> createState() => _WelcomeScreenState();
}

class _WelcomeScreenState extends State<WelcomeScreen> {
  final String studentName = 'Escribe tu nombre';
  int pendingTasks = 3;

  void _completeTask() {
    if (pendingTasks == 0) {
      return;
    }

    setState(() {
      pendingTasks--;
    });
  }

  void _addTask() {
    setState(() {
      pendingTasks++;
    });
  }

  @override
  Widget build(BuildContext context) {
    final statusMessage = pendingTasks == 0
        ? '¡Excelente! No tienes tareas pendientes.'
        : 'Aún tienes tareas por organizar.';

    return Scaffold(
      appBar: AppBar(
        title: const Text('TaskFlow'),
        centerTitle: true,
      ),
      body: Padding(
        padding: const EdgeInsets.all(24),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            Text(
              '¡Hola, $studentName!',
              style: Theme.of(context).textTheme.headlineMedium,
            ),
            const SizedBox(height: 12),
            Text(statusMessage),
            const SizedBox(height: 28),
            Card(
              child: Padding(
                padding: const EdgeInsets.all(20),
                child: Row(
                  children: [
                    const Icon(Icons.pending_actions),
                    const SizedBox(width: 12),
                    Text('Tareas pendientes: $pendingTasks'),
                  ],
                ),
              ),
            ),
            const SizedBox(height: 24),
            Wrap(
              spacing: 12,
              children: [
                ElevatedButton.icon(
                  onPressed: _addTask,
                  icon: const Icon(Icons.add),
                  label: const Text('Agregar tarea'),

3

Comprender setState()

setState() recibe una función. Dentro de ella se cambia el dato que pertenece al estado. Al terminar, Flutter sabe que debe volver a ejecutar build(). Por eso se actualizan el contador y el mensaje sin que modifiques cada widget manualmente.

setState(() {
  pendingTasks--;
});

Evita este error: si escribes solo pendingTasks--;, el valor cambia en memoria pero Flutter no recibe el aviso para redibujar la pantalla.

4

Probar todos los estados posibles

  1. Pulsa Agregar tarea: el contador debe aumentar.
  2. Pulsa Completar una tarea: el contador debe disminuir.
  3. Llega a cero: el mensaje cambia.
  4. En cero, el botón de completar queda deshabilitado porque onPressed: null desactiva botones Material.
  5. Agrega una tarea y comprueba que el botón se habilita otra vez.
5

Distinguir const, final y una variable de estado

final String studentNameSe asigna una vez al crearse la pantalla y luego no se reasigna.
int pendingTasksEs modificable porque representa un valor que cambia durante la vida de la pantalla.
const Text(...)Se usa únicamente cuando el widget no depende de información que cambia.
final statusMessageSe calcula de nuevo cada vez que build() se ejecuta, según el estado actual.

1

Preparar el proyecto

Abre el TaskFlow que terminaste en la sesión 2. Comprueba que inicia antes de cambiar la pantalla principal.

cd taskflow
flutter run

En esta sesión los datos serán locales: todavía no hay API ni base de datos. Al finalizar, Task representará datos y TaskCard representará su interfaz.

2

Inicio · comprender layout y repetición

Flutter aplica la regla “las restricciones bajan, los tamaños suben y el padre posiciona”. Revisa la guía oficial Understanding constraints. Una tarea repetida no exige copiar cinco tarjetas: se modela una vez y se construye por cada elemento de una lista.

Decisión: Task no dibuja widgets. TaskCard recibe una tarea y decide cómo se ve. La pantalla crea la lista de tarjetas.
3

Desarrollo A · crear datos locales

En lib/main.dart, debajo de TaskFlowApp, agrega el modelo y cinco datos de prueba. Cada propiedad existe porque la UI la mostrará; el id preparará la navegación de la sesión siguiente.

class Task {
  const Task({
    required this.id,
    required this.title,
    required this.description,
    required this.priority,
    required this.isCompleted,
  });

  final int id;
  final String title;
  final String description;
  final String priority;
  final bool isCompleted;
}

const demoTasks = [
  Task(id: 1, title: 'Leer documentación', description: 'Revisar ListView.builder', priority: 'Alta', isCompleted: false),
  Task(id: 2, title: 'Diseñar la pantalla', description: 'Definir la tarjeta de tarea', priority: 'Media', isCompleted: false),
  Task(id: 3, title: 'Preparar evidencia', description: 'Tomar captura del avance', priority: 'Baja', isCompleted: true),
  Task(id: 4, title: 'Organizar el backlog', description: 'Priorizar pendientes', priority: 'Alta', isCompleted: false),
  Task(id: 5, title: 'Revisar código', description: 'Ejecutar flutter analyze', priority: 'Media', isCompleted: false),
];

Los datos son const porque no cambian en esta sesión. Más adelante provendrán de una API y se administrarán con arquitectura MVVM.

4

Desarrollo B · extraer TaskCard

ListTile ofrece una fila Material con título, subtítulo e iconos. La tarjeta no necesita conocer la lista completa.

class TaskCard extends StatelessWidget {
  const TaskCard({super.key, required this.task});

  final Task task;

  @override
  Widget build(BuildContext context) {
    return Card(
      child: ListTile(
        leading: Icon(
          task.isCompleted ? Icons.check_circle : Icons.radio_button_unchecked,
          color: task.isCompleted ? Colors.green : null,
        ),
        title: Text(task.title),
        subtitle: Text(task.priority + ' · ' + task.description),
        trailing: const Icon(Icons.chevron_right),
      ),
    );
  }
}

Comprueba: no verás tarjetas hasta que una pantalla construya una por cada objeto de demoTasks.

5

Desarrollo C · crear la lista bajo demanda

La API oficial indica que ListView.builder crea elementos a demanda, por lo que es adecuada para listas grandes. Cambia home: const WelcomeScreen() por home: const TaskListScreen() y agrega:

class TaskListScreen extends StatelessWidget {
  const TaskListScreen({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Mis tareas')) ,
      body: ListView.builder(
        padding: const EdgeInsets.all(16),
        itemCount: demoTasks.length,
        itemBuilder: (context, index) {
          final task = demoTasks[index];
          return TaskCard(task: task);
        },
      ),
    );
  }
}
itemCount: limita los índices válidos y permite que la lista estime correctamente su extensión de desplazamiento.

CODELAB 04 · SEMANA 2

Navegar entre listado y detalle

TaskFlow abrirá una tarea por su id y regresará al listado mediante rutas declarativas.

Objetivo: configurar go_router, enviar un parámetro de ruta y construir una pantalla de detalle que reutiliza los datos de la sesión 3.

Desarrollo · 15–85 minInstalar go_router, declarar rutas, enviar id y construir el detalle.
Cierre · 85–120 minProbar varias rutas, completar el avance autónomo y evidenciar la sesión con commit y push.
1

Preparar el listado de la sesión 3

Este codelab parte de Task, demoTasks, TaskCard y TaskListScreen. Ejecuta la app y confirma que hay cinco tarjetas antes de introducir navegación.

cd taskflow
flutter run

Una ruta es una dirección. El id forma parte de la dirección para que el detalle identifique qué tarea mostrar.

2

Inicio · instalar go_router

go_router proporciona rutas declarativas basadas en URL, parámetros y deep links. Instala la versión compatible con el SDK del proyecto, sin escribir una versión fija.

flutter pub add go_router

Agrega import 'package:go_router/go_router.dart'; en main.dart. Comprueba que pubspec.yaml registra la dependencia.

3

Desarrollo A · declarar rutas y usar MaterialApp.router

Después de demoTasks, declara las rutas. El patrón /task/:id captura un id; la pantalla lo transforma a entero y busca el dato local.

final appRouter = GoRouter(
  routes: [
    GoRoute(
      path: '/',
      builder: (context, state) => const TaskListScreen(),
    ),
    GoRoute(
      path: '/task/:id',
      builder: (context, state) {
        final taskId = int.parse(state.pathParameters['id']!);
        return TaskDetailScreen(taskId: taskId);
      },
    ),
  ],
);

Reemplaza el MaterialApp anterior por:

return MaterialApp.router(
  debugShowCheckedModeBanner: false,
  title: 'TaskFlow',
  theme: ThemeData(
    colorScheme: ColorScheme.fromSeed(seedColor: Colors.indigo),
    useMaterial3: true,
  ),
  routerConfig: appRouter,
);
4

Desarrollo B · hacer TaskCard navegable

Agrega una acción opcional a TaskCard. Así el componente es reutilizable y la pantalla decide qué debe ocurrir al tocarlo.

final VoidCallback? onTap;

return Card(
  child: ListTile(
    onTap: onTap,
    title: Text(task.title),
    subtitle: Text(task.priority + ' · ' + task.description),
    trailing: const Icon(Icons.chevron_right),
  ),
);

Actualiza el constructor con this.onTap. Después, en el itemBuilder de TaskListScreen, usa:

return TaskCard(
  task: task,
  onTap: () => context.push('/task/' + task.id.toString()),
);
5

Desarrollo C · construir TaskDetailScreen

Agrega esta clase al final de main.dart. Hasta que exista Repository, demoTasks es la fuente temporal de datos.

class TaskDetailScreen extends StatelessWidget {
  const TaskDetailScreen({super.key, required this.taskId});

  final int taskId;

  @override
  Widget build(BuildContext context) {
    final task = demoTasks.firstWhere((item) => item.id == taskId);

    return Scaffold(
      appBar: AppBar(title: const Text('Detalle de tarea')) ,
      body: Padding(
        padding: const EdgeInsets.all(24),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            Text(task.title, style: Theme.of(context).textTheme.headlineSmall),
            const SizedBox(height: 16),
            Text(task.description),
            const SizedBox(height: 16),
            Chip(label: Text('Prioridad: ' + task.priority)),
            const SizedBox(height: 12),
            Text(task.isCompleted ? 'Estado: completada' : 'Estado: pendiente'),
            const Spacer(),
            FilledButton.tonalIcon(
              onPressed: () => context.pop(),
              icon: const Icon(Icons.arrow_back),
              label: const Text('Volver al listado'),
            ),
          ],
        ),
      ),
    );
  }
}
