CODELAB 01

Crear y ejecutar la primera versión de TaskFlow

Al terminar tendrás un proyecto Flutter ejecutándose en Android y una pantalla de bienvenida creada a partir de datos Dart.

Aprenderás a: reconocer la estructura de un proyecto Flutter, crear variables y colecciones en Dart, y mostrar sus valores mediante widgets.
1

Verificar Flutter y el dispositivo

Abre una terminal dentro de tu carpeta de trabajo. El primer comando revisa la instalación; el segundo lista los dispositivos disponibles.

flutter doctor
flutter devices

Resultado esperado: flutter doctor muestra una lista de verificaciones y flutter devices muestra un emulador o teléfono. Si no aparece ninguno, inicia el emulador, espera su arranque completo y ejecuta el segundo comando otra vez.

¿Qué hago con un aviso de licencia de Android?

Ejecuta flutter doctor --android-licenses, responde y cuando corresponda y repite flutter doctor. Las licencias no se aceptan dentro del código Dart.

2

Crear el proyecto

Un proyecto Flutter contiene el código Dart y la configuración para Android. Crea la aplicación con un nombre técnico en minúsculas.

flutter create taskflow
cd taskflow
code .

Si code . no funciona, abre manualmente la carpeta taskflow en tu editor.

Explora el proyecto antes de editar. lib/main.dart es el punto de entrada. pubspec.yaml declara el nombre, la versión y las dependencias. La carpeta android/ contiene ajustes específicos de Android. Por ahora solo trabajaremos en lib/main.dart.
3

Ejecutar la plantilla original

Primero confirma que el proyecto generado funciona. Así podrás distinguir un problema del entorno de un problema introducido al programar.

flutter run

Comprobación: se abre una app de contador. Pulsa el botón flotante con + y verifica que el número aumenta. Detén la ejecución con q en la terminal o con Stop en el editor.

4

Crear la aplicación y su primera pantalla

Abre lib/main.dart, elimina el contenido generado y pega el siguiente código completo. main() es el inicio de Dart; runApp() entrega a Flutter el widget raíz que debe dibujar.

import 'package:flutter/material.dart';

void main() {
  runApp(const TaskFlowApp());
}

class TaskFlowApp extends StatelessWidget {
  const TaskFlowApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      title: 'TaskFlow',
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.indigo),
        useMaterial3: true,
      ),
      home: const WelcomeScreen(),
    );
  }
}

class WelcomeScreen extends StatelessWidget {
  const WelcomeScreen({super.key});

  @override
  Widget build(BuildContext context) {
    const studentName = 'Escribe tu nombre';
    const pendingTasks = 3;
    const courseName = 'Desarrollo de aplicaciones móviles';

    return Scaffold(
      appBar: AppBar(
        title: const Text('TaskFlow'),
        centerTitle: true,
      ),
      body: Padding(
        padding: const EdgeInsets.all(24),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            const Icon(Icons.check_circle_outline, size: 56),
            const SizedBox(height: 24),
            Text(
              '¡Hola, $studentName!',
              style: Theme.of(context).textTheme.headlineMedium,
            ),
            const SizedBox(height: 12),
            Text('Bienvenido/a a $courseName.'),
            const SizedBox(height: 32),
            Card(
              child: Padding(
                padding: const EdgeInsets.all(20),
                child: Row(
                  children: [
                    const Icon(Icons.pending_actions),
                    const SizedBox(width: 12),
                    Text('Tareas pendientes: $pendingTasks'),
                  ],
                ),
              ),
            ),
          ],
        ),
      ),
    );
  }
}

Importante: los valores declarados con const no cambian durante esta sesión. Por eso WelcomeScreen extiende StatelessWidget: solo presenta información fija.

5

Leer el código antes de modificarlo

MaterialAppConfigura el título, el tema y la primera pantalla de la aplicación.
ScaffoldProporciona una estructura Material: barra superior y cuerpo de pantalla.
ColumnOrganiza widgets verticalmente, uno debajo de otro.
Text('... $variable')La interpolación con $ inserta una variable dentro de una cadena.
SizedBoxAgrega un espacio visual fijo sin dibujar contenido.
6

Usar Hot Reload

Ejecuta la app con flutter run. Cambia el valor de studentName por tu nombre y pendingTasks por otro número. Guarda el archivo. Flutter aplicará hot reload, una actualización de la interfaz sin reiniciar por completo la aplicación.

Comprobación: los valores nuevos aparecen en pantalla. Si no cambian, guarda de nuevo; si persiste, realiza Hot Restart desde el editor.

CODELAB 02

Hacer que el panel responda a acciones

TaskFlow dejará de mostrar un contador fijo. Ahora podrá agregar y completar tareas a partir de interacciones de la persona usuaria.

Aprenderás a: diferenciar widgets con y sin estado, explicar setState() y actualizar una interfaz mediante botones.
1

Identificar qué dato debe cambiar

En la sesión anterior, pendingTasks era una constante. Pero una tarea pendiente puede agregarse o completarse. Esa información que cambia y obliga a redibujar la interfaz se llama estado.

Idea clave: no se cambia el texto directamente. Se cambia el estado y Flutter ejecuta otra vez build() para describir la nueva pantalla.
2

Convertir la pantalla en StatefulWidget

Conserva main() y TaskFlowApp. Reemplaza solamente la clase WelcomeScreen por este bloque. Ahora hay dos clases: el widget inmutable y la clase privada que contiene su estado modificable.

class WelcomeScreen extends StatefulWidget {
  const WelcomeScreen({super.key});

  @override
  State<WelcomeScreen> createState() => _WelcomeScreenState();
}

class _WelcomeScreenState extends State<WelcomeScreen> {
  final String studentName = 'Escribe tu nombre';
  int pendingTasks = 3;

  void _completeTask() {
    if (pendingTasks == 0) {
      return;
    }

    setState(() {
      pendingTasks--;
    });
  }

  void _addTask() {
    setState(() {
      pendingTasks++;
    });
  }

  @override
  Widget build(BuildContext context) {
    final statusMessage = pendingTasks == 0
        ? '¡Excelente! No tienes tareas pendientes.'
        : 'Aún tienes tareas por organizar.';

    return Scaffold(
      appBar: AppBar(
        title: const Text('TaskFlow'),
        centerTitle: true,
      ),
      body: Padding(
        padding: const EdgeInsets.all(24),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            Text(
              '¡Hola, $studentName!',
              style: Theme.of(context).textTheme.headlineMedium,
            ),
            const SizedBox(height: 12),
            Text(statusMessage),
            const SizedBox(height: 28),
            Card(
              child: Padding(
                padding: const EdgeInsets.all(20),
                child: Row(
                  children: [
                    const Icon(Icons.pending_actions),
                    const SizedBox(width: 12),
                    Text('Tareas pendientes: $pendingTasks'),
                  ],
                ),
              ),
            ),
            const SizedBox(height: 24),
            Wrap(
              spacing: 12,
              children: [
                ElevatedButton.icon(
                  onPressed: _addTask,
                  icon: const Icon(Icons.add),
                  label: const Text('Agregar tarea'),
                ),
                OutlinedButton.icon(
                  onPressed: pendingTasks == 0 ? null : _completeTask,
                  icon: const Icon(Icons.done),
                  label: const Text('Completar una tarea'),
                ),
              ],
            ),
          ],
        ),
      ),
    );
  }
}
3

Comprender setState()

setState() recibe una función. Dentro de ella se cambia el dato que pertenece al estado. Al terminar, Flutter sabe que debe volver a ejecutar build(). Por eso se actualizan el contador y el mensaje sin que modifiques cada widget manualmente.

setState(() {
  pendingTasks--;
});

Evita este error: si escribes solo pendingTasks--;, el valor cambia en memoria pero Flutter no recibe el aviso para redibujar la pantalla.

4

Probar todos los estados posibles

  1. Pulsa Agregar tarea: el contador debe aumentar.
  2. Pulsa Completar una tarea: el contador debe disminuir.
  3. Llega a cero: el mensaje cambia.
  4. En cero, el botón de completar queda deshabilitado porque onPressed: null desactiva botones Material.
  5. Agrega una tarea y comprueba que el botón se habilita otra vez.
5

Distinguir const, final y una variable de estado

final String studentNameSe asigna una vez al crearse la pantalla y luego no se reasigna.
int pendingTasksEs modificable porque representa un valor que cambia durante la vida de la pantalla.
const Text(...)Se usa únicamente cuando el widget no depende de información que cambia.
final statusMessageSe calcula de nuevo cada vez que build() se ejecuta, según el estado actual.

RETO AUTÓNOMO · 25 MIN

Agregar un objetivo diario

Declara const dailyGoal = 5;. Crea el estado completedTasks y muestra “Completadas hoy: X de 5”. Al completar una tarea, reduce pendientes y aumenta completadas. El botón debe deshabilitarse cuando no haya tareas pendientes. Como evidencia de este trabajo autónomo, realiza git add ., el commit feat: agregar estado de tareas y git push origin main.

Errores frecuentes de la sesión 2

“The method 'setState' isn't defined”
El método solo existe dentro de una clase que extiende State<...>. Revisa que el cambio esté en _WelcomeScreenState.
El contador cambia, pero la pantalla no
La modificación de pendingTasks debe estar dentro de setState(() { ... }).
“A value of type int can't be assigned…”
Comprueba que pendingTasks no se declaró con const o final.
Error con State<WelcomeScreen>
Escribe los símbolos menor y mayor normalmente en Dart. El navegador los muestra escapados para poder enseñar código HTML.
