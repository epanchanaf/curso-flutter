IDEA CENTRAL

Una aplicación móvil no es solo una colección de pantallas. Es un sistema que recibe eventos del usuario, administra estado y se comunica con datos externos.

Durante el curso se conecta ese flujo completo: interfaz → lógica → API → interfaz.

PROYECTO INTEGRADOR

TaskFlow: una aplicación de gestión de tareas.

TaskFlow es el caso guía. Su alcance es pequeño, pero suficiente para practicar las decisiones técnicas más importantes de una app conectada a servicios web.

01

Consultar

Mostrar una lista de tareas desde una API, con estados de carga, contenido vacío y error.

02

Gestionar

Crear, editar y eliminar tareas usando formularios, validaciones y solicitudes HTTP.

03

Comunicar

Informar al usuario qué ocurre: progreso, confirmaciones, errores recuperables y resultados de búsqueda.

04

Entregar

Documentar el proyecto, probar componentes esenciales y construir un APK listo para instalar.

ARQUITECTURA DEL PROYECTO

MVVM + Repository: ordenar para poder crecer.

La arquitectura define responsabilidades. Evita que los widgets hagan peticiones HTTP directamente y facilita localizar, probar y cambiar el código.

UI

View

Pantallas y widgets. Muestran información y capturan toques, texto o acciones del usuario.

↕
STATE

ViewModel

Convierte los datos en estado de interfaz: carga, lista de tareas, error y acciones disponibles.

↕
DATA

Repository

Es la fuente de verdad de las tareas. Decide cómo obtener, transformar o actualizar datos.

↕
HTTP

API Service

Aísla los detalles técnicos de la red: URL, método HTTP, encabezados y conversión de respuestas.

Flujo de datos: una persona toca “Guardar” → la vista invoca una acción del ViewModel → el repositorio usa el servicio de API → el ViewModel actualiza el estado → la vista se vuelve a dibujar.

CAJA DE HERRAMIENTAS

Pocas herramientas, usadas con intención.

La selección evita sobrecargar el curso con bibliotecas que resuelven el mismo problema. Cada paquete se presenta cuando el proyecto lo necesita.

NecesidadHerramientaUso en TaskFlow
Estado + DIprovider + ChangeNotifierEl ViewModel publica estados y Provider entrega ApiService, Repository y ViewModel sin crear dependencias globales.
Conexión RESTdioCliente HTTP centralizado con URL base, timeouts, cabeceras e interceptores para token y diagnóstico.
Navegacióngo_routerDeclara rutas para listado, detalle, formulario y configuración; permite enviar parámetros de forma explícita.
Preferenciasshared_preferencesGuarda datos no críticos: tema, nombre visible y último filtro. Se usará su API asíncrona moderna.
Tokens realesflutter_secure_storageSolo si la API usa autenticación. Un token nunca se guarda en preferencias comunes.
Calidadflutter_lints + mocktailEl primero detecta problemas de estilo y el segundo permite simular repositorios en pruebas sin llamar a internet.
FechasintlDa formato legible a fechas y horas en tareas, respetando idioma y configuración regional.
VersionadoGit + GitHubRegistra únicamente el trabajo autónomo de cada sesión y publica el avance en el repositorio remoto.
Decisión didáctica: no se incorporará Bloc, Riverpod, GetX, get_it, Retrofit o Firebase en el núcleo del curso. Son herramientas válidas, pero introducir varias soluciones al mismo tiempo reduciría el tiempo disponible para comprender el flujo de datos, la API y las pruebas.

CONTROL DE VERSIONES · REQUISITO TRANSVERSAL

Al finalizar el trabajo autónomo de cada sesión

El estudiante prueba su avance, realiza un commit con el mensaje sugerido en la ruta del proyecto y lo publica en GitHub. El ejemplo guiado se utiliza para aprender; la evidencia que se versiona es la adaptación autónoma a TaskFlow.

git status
git add .
git commit -m "feat: describir avance autónomo"
git push origin main

Antes del primer push, cada estudiante debe crear o tener asignado un repositorio GitHub y configurarlo como remoto origin.

RUTA DE APRENDIZAJE

Semana por semana, sesión por sesión.

Cada sesión se organiza en tres momentos: inicio, desarrollo y cierre. Abre una semana para estudiar su secuencia, conceptos y prácticas incrementales.

METODOLOGÍA

Una clase con tres momentos y dos tipos de práctica.

1

Inicio

Activa conocimientos previos, sitúa el problema y presenta el objetivo de aprendizaje de la sesión.

2

Desarrollo

Combina explicación conceptual, ejemplo guiado por el docente y práctica autónoma acompañada.

3

Cierre

Verifica resultados, corrige dificultades, registra evidencia y enlaza con la siguiente sesión.

Ejemplo guiado significa que docente y estudiantes construyen una solución en conjunto. Práctica autónoma incremental es el reto que cada estudiante implementa durante la clase sobre su propia app, aplicando lo recién aprendido.
