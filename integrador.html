TRABAJO INTEGRADOR · 16 AVANCES

Una sesión, una mejora observable en la app final.

El trabajo autónomo no es un ejercicio aislado. Después de cada clase, el estudiante aplica el concepto revisado a TaskFlow y conserva una evidencia concreta en su repositorio.

CÓMO USAR ESTA RUTA

El ciclo de cada sesión

  1. Comprender: seguir el ejemplo del docente.
  2. Transferir: aplicar el mismo concepto en TaskFlow.
  3. Comprobar: ejecutar, probar y guardar evidencia.
  4. Versionar: hacer commit y push del trabajo autónomo.
Producto final: una aplicación Android para gestionar tareas, organizada con MVVM, conectada a una API REST, con operaciones CRUD, manejo de errores, pruebas básicas y un APK instalable.

REGLA DE ENTREGA POR SESIÓN

El repositorio se actualiza con el trabajo autónomo, no con la demostración guiada.

Cuando el estudiante complete el avance indicado en cada tarjeta, debe verificar que funciona, ejecutar el commit propuesto y hacer git push origin main. El historial de GitHub será la evidencia del progreso continuo del proyecto integrador.

git status
git add .
git commit -m "mensaje propuesto para la sesión"
git push origin main
SEMANA 1

Base de la aplicación

Sesión 1 · Fundamentos y layouts básicos

Construir la bienvenida de TaskFlow

Aplicar: creación de proyecto, variables Dart, Scaffold, Column, Row, Card y Text.

Avance: crear una pantalla inicial con el nombre de la app, saludo personalizado, mensaje motivacional y tarjeta de “tareas pendientes”. Usar una columna para la pantalla y una fila para el icono y contador.

Evidencia: captura de pantalla y commit feat: crear pantalla de bienvenida.

Sesión 2 · Estado local

Hacer interactivo el panel

Aplicar: StatefulWidget, variables de estado, setState() y botones.

Avance: convertir la bienvenida en un panel que permita agregar y completar tareas. El número de pendientes debe cambiar y el botón de completar debe deshabilitarse al llegar a cero.

Evidencia: video corto o GIF del contador y commit feat: agregar estado de tareas.

SEMANA 2

Interfaz navegable

Sesión 3 · Layouts y listas

Mostrar tareas locales

Aplicar: modelos simples, listas, ListView.builder, tarjetas y widgets reutilizables.

Avance: crear una lista local de al menos cinco tareas y un widget TaskCard. Cada tarjeta muestra título, prioridad, estado e icono.

Evidencia: listado desplazable y commit feat: mostrar listado local de tareas.

Sesión 4 · Navegación

Agregar el detalle de una tarea

Aplicar: rutas con go_router y parámetros de navegación.

Avance: al tocar una tarjeta, navegar a una pantalla de detalle que reciba el id o la tarea seleccionada y presente su información completa.

Evidencia: flujo lista → detalle → regresar y commit feat: agregar detalle de tarea.

SEMANA 3

Diseño y organización

Sesión 5 · Especificación y modelo

Definir el alcance de TaskFlow

Aplicar: historias de usuario, requisitos y modelado de datos.

Avance: definir la clase Task con id, título, descripción, prioridad y estado. Documentar cinco historias de usuario y el flujo de pantallas en el README.

Evidencia: README inicial y commit docs: definir alcance y modelo de TaskFlow.

Sesión 6 · MVVM

Separar responsabilidades

Aplicar: carpetas por funcionalidad, View, ViewModel, Repository y Service.

Avance: mover el modelo y las pantallas a features/tasks; crear el contrato TaskRepository y TasksViewModel que, por ahora, entregue datos locales.

Evidencia: estructura de carpetas compilando y commit refactor: organizar feature tasks con MVVM.

SEMANA 4

Datos remotos

Sesión 7 · HTTP y JSON

Consultar tareas desde API

Aplicar: Dio, Future, async/await, JSON y fromJson().

Avance: crear TaskApiService con una solicitud GET al endpoint elegido; transformar la respuesta en una lista de Task.

Evidencia: respuesta visible en consola o lista temporal y commit feat: consultar tareas desde API.

Sesión 8 · Estado asíncrono

Conectar API con la interfaz

Aplicar: Repository, Provider, ChangeNotifier y estados carga/éxito/error/vacío.

Avance: usar TaskRepository desde TasksViewModel y sustituir el listado local por datos remotos. Diseñar una vista para cada estado posible.

Evidencia: botón Reintentar funcional y commit feat: integrar estado remoto de tareas.

SEMANA 5

Gestión de datos

Sesión 9 · Formularios

Crear y editar desde una pantalla

Aplicar: Form, TextFormField, validaciones y selectores.

Avance: agregar una pantalla de formulario reutilizable para registrar o editar una tarea. Validar título obligatorio y prioridad.

Evidencia: formulario con mensajes claros y commit feat: agregar formulario de tareas.

Sesión 10 · CRUD remoto

Modificar los datos de la API

Aplicar: POST, PATCH/PUT, DELETE, toJson(), SnackBar y confirmaciones.

Avance: conectar el formulario a crear y editar; añadir eliminación desde detalle con diálogo de confirmación; refrescar la lista después de cada operación.

Evidencia: recorrido CRUD completo y commit feat: completar CRUD de tareas.

SEMANA 6

Resiliencia y calidad

Sesión 11 · Errores

Diseñar fallos recuperables

Aplicar: excepciones, try/catch, timeouts, mensajes y reintentos.

Avance: mapear al menos tres errores: sin conexión, error de servidor y validación fallida. Mostrar acciones comprensibles y bloquear el envío duplicado.

Evidencia: capturas de estados de error y commit feat: manejar errores de red.

Sesión 12 · Pruebas

Proteger comportamientos críticos

Aplicar: flutter_test, fakes o Mocktail y pruebas de widget.

Avance: escribir una prueba de Task.fromJson, una del ViewModel/Repository, una de validación y una que compruebe el estado de carga o error.

Evidencia: salida exitosa de flutter test y commit test: cubrir flujo esencial de tareas.

SEMANA 7

Utilidad y experiencia

Sesión 13 · Persistencia

Conservar una preferencia útil

Aplicar: shared_preferences o almacenamiento seguro si existe autenticación.

Avance: persistir el tema, nombre de usuario o último filtro. Si el proyecto usa login real, guardar el token con flutter_secure_storage.

Evidencia: cerrar y volver a abrir la app preservando la opción y commit feat: persistir preferencias de usuario.

Sesión 14 · Búsqueda y accesibilidad

Encontrar y comprender tareas

Aplicar: filtros, orden, estado “sin resultados” y criterios de accesibilidad.

Avance: añadir búsqueda por título, filtro por estado o prioridad, limpiar filtros y revisar contraste, texto y objetivos táctiles.

Evidencia: búsqueda demostrable y commit feat: agregar búsqueda y filtros.

SEMANA 8

Entrega profesional

Sesión 15 · Refactor y documentación

Preparar el repositorio

Aplicar: formato, análisis estático, README y documentación técnica.

Avance: ejecutar dart format ., flutter analyze y pruebas; documentar instalación, arquitectura, API, capturas, funcionalidades y límites conocidos.

Evidencia: README completo y commit docs: preparar entrega final.

Sesión 16 · APK y demo

Entregar y defender el proyecto

Aplicar: compilación release, pruebas de aceptación y comunicación técnica.

Avance: generar APK, instalarlo, recorrer los flujos críticos y presentar problema, arquitectura, API y demostración de CRUD.

Evidencia: APK, enlace de repositorio y commit build: generar apk de entrega.
